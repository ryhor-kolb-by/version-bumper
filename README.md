# Version Bumper

Учебное приложение для практики по CI/CD.
Маленький калькулятор следующей версии релиза по правилам semver.

## Запуск

    npm ci
    npm run dev

Откроется на http://localhost:5173

Нужен Node 22 (версия зафиксирована в `.nvmrc`).

## Проверки

    npm test        # 9 тестов
    npm run lint
    npm run build

Все три команды должны быть зелёными до того, как вы начнёте задание.
Если что-то падает на чистом клоне — позовите преподавателя, это не ваша ошибка.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/lib/version.js` | Логика: разбор, повышение и сравнение версий |
| `src/lib/version.test.js` | Тесты к этой логике |
| `src/App.jsx` | Интерфейс |
| `src/App.css` | Стили. Цвет акцента — переменная `--accent` |
| `vite.config.js` | Сборка. Здесь SHA коммита попадает в приложение |

## Футер — ваш главный индикатор

Внизу страницы выводятся SHA коммита и тип окружения:

| Где открыто | commit | env |
|---|---|---|
| Локально | `local` | `local` |
| Preview-деплой | SHA вашей ветки | `preview` |
| Production-деплой | SHA из `main` | `production` |

По ним всегда видно, какую именно сборку вы смотрите. Пригодится,
когда откроете preview и production рядом.

## Задание

Построить конвейер, при котором сломанный код физически не может
попасть в продакшн.

1. Написать `.github/workflows/ci.yml`, который на каждый push и PR
   запускает тесты.
2. Намеренно сломать логику, открыть PR и увидеть красный CI.
3. Включить защиту ветки `main` — убедиться, что красный PR не мержится.
4. Починить, смержить.
5. Подключить репозиторий к Vercel, получить production URL.
6. Открыть PR с видимым изменением и найти preview-ссылку.
7. Добавить в пайплайн параллельный job `lint` и job `build` с `needs`.

Подробные шаги — в методичке к занятию.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Workflow вообще не запустился | Путь ровно `.github/workflows/ci.yml`; отступы в YAML — только пробелы |
| `npm ci` падает в Actions | `package-lock.json` должен быть закоммичен |
| Job висит и не завершается | В `package.json` должно быть `vitest run`, а не `vitest` |
| Правки в YAML «не применились» | Workflow выполняется только после push — локально он не запускается |
| Vercel собрал, но белый экран | Читайте build logs в панели Vercel |

Отладка пайплайна идёт через push — цикл медленнее, чем вы привыкли.
Это нормально, так у всех.
